# 仮説工房（god-thinking）

家庭連合／統一思想の枠組みで「神の心情と人間創造」についての理論的仮説を書き、
記事として読み、問いを立て、視点を開くためのツール。

**これは何ではないか。**

- 教義の正しさを主張する道具ではない。仮説を置く場所であって、真理を配る場所ではない
- 仮説の真偽を判定しない。できるのは整合性・反証条件・出典実在の検査まで
- 布教・護教のための資料ではない
- 原典のビューアではない。原典は引用としてしか現れない

---

## 絶対的な制約

### 1. 依存ゼロ

- ビルドは **Python 3.11 標準ライブラリのみ**。`pip install` を必要としない
- `package.json` を置かない。npm を使わない

### 2. オフラインで完全に動く

- CDN からのスクリプト・フォント・画像を読み込まない

### 3. `file://` で開ける

- `index.html` はダブルクリックで開いて完全に機能する
- **`fetch()` を使わない。** CORS で失敗する
- **`<script type="module">` を使わない。** `file://` で動かない
- データは `window.X = ...` 形式の `.js` としてビルドが生成する

### 4. 原典は読み取り専用・非公開

- **`docs/` を書き換えない。** ビルドは読むだけ
- `docs/` は `.gitignore` 対象。著作権がある
- OCR 崩れや混入は**警告表示までで、直さない**

### 5. `innerHTML` は 1 箇所だけ

- 使ってよいのは `assets/js/views/article.js` の本文挿入のみ
- そこに入るのは自分のビルドが生成した HTML であり、外部由来ではない
- **それ以外はすべて `document.createElement`**

## 構成

```
docs/                   原典（非公開・読み取り専用）
config/studio.json      論点・観点・地雷・既出対応づけの定義
hypotheses/<slug>.md    仮説記事（JSON frontmatter + 本文）
scripts/markdown.py     Markdown 変換
scripts/validate.py     検証 25 項目
scripts/build.py        ビルド本体
data/*.js               生成物（コミットする）
index.html              唯一のページ
assets/css/             素の CSS
assets/js/              IIFE + グローバル。ES modules を使わない
.claude/specs/          仕様書
```

---

## コマンド

```bash
python scripts/build.py     # 検証 → 変換 → 集計 → data/*.js 生成
```

そのあと `index.html` をダブルクリックして確認する。

**検証が通らなければ `data/*.js` は更新されない。** これは意図した挙動。

## ドメイン固有のルール

### 仮説には必ず持たせるもの

| 項目 | 理由 |
|---|---|
| `mode`（比喩 / 構造的対応） | 科学を雰囲気で流用すると疑似科学になる。何を主張していないかを先に言う |
| `terrain`（空白地 / 拡張 / 留保地 / 係争地） | 原典が既に言っていることを新説として出さないため |
| `falsifiers` | 反証条件のない仮説は置かない |
| `questions` | 答えより問いを残すための工房である |
| `mines`（全 7 件を列挙） | 書き忘れと「検討して触れないと判断した」を区別する |

### 原典の引用

- 専用記法 `:::quote n` を使う。ブロック引用（`>`）は著者自身の強調
- 引用本文は**逐語**。ビルドが原典との完全一致を検査する
- 1 箇所 200 字 / 1 記事合計 600 字まで
- **`anchor` は生成物に出力しない。** 原典の逐語なので、検証にだけ使う

### 原典の癖（把握済み）

- 原理講論は Markdown 見出しをほぼ持たない。前編 02/03/04/06/07 は**1 節が 1 行**
- 統一思想の見出しは OCR で採番が壊れている（`（一）`→`I`、`（二）`→`14` など）
- 照合は**空白類を除去した正規化後**に行う。そうしないと成立しない
- 既知の欠損: 前編 03 に後編緒論が混入 / 前編 07 の第一節が欠落 /
  後編 04 の H1 と章題が不一致 / 前編 01 に空の `## 後編`
