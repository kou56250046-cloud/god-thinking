# 創造シミュレータ — 要件

## 背景

家庭連合／統一原理の枠組みで、神が人間を創造したときの心情を具体的に考察したい。

中心にあるのは次の問いである。

> 全能である神が、なぜ堕落を防げなかったのか。あるいは、なぜ防が**なかった**のか。

この問いは、説明文を読んで納得する種類のものではない。神が置かれていた条件に自分が立ち、
同じ設計判断を自分の手で何度も試し、どの選択肢でも望むものが揃わないことに突き当たって
初めて近づけるものだと考える。

そこで、創造の設計変数をパラメータ化し、条件を変えて「世界を創造」すると、その世界で
何が成立し何が失われるかを原理に基づく明示ルールで判定する装置を作る。

判定ロジックは原理講論の原則（授受作用・四位基台・三大祝福・間接主管圏など）から導き、
どの原則を根拠にその判定になったかを常に提示する。ユーザーが判定を鵜呑みにせず、
根拠に戻って検証できることを重視する。

既存に該当するツールは無い。新規プロジェクトとして作る。

---

## このツールが主張しないこと

**画面に常時表示する固定文（文言を仕様で確定する）:**

> このツールは、原理講論の原則から筋を通すと何が言えるかを機械的に判定するものです。
> 教義の正しさを主張するものではありません。判定の根拠には、原典の記述と、
> このツールが推論で補ったものが混在しています。「推論」の印が付いた根拠には、
> 原典に直接の記述がありません。

## 受入条件

### 動作の基本

- [ ] `index.html` をエクスプローラからダブルクリックして開くと、ローカルサーバーなしで
      全機能が動作する
- [ ] ブラウザをオフラインにしても全機能が動作する
- [ ] 上記の固定文が、画面の所定位置に常時表示されている

### パラメータ設定

- [ ] 創造パラメータ 7 項目をすべて画面上で設定できる

  | # | パラメータ | 取りうる値 | 既定値 |
  |---|---|---|---|
  | 1 | 自由意志 | なし / 制限付き / 完全 | 完全 |
  | 2 | 成長期間 | あり / なし（完成体で創造） | あり |
  | 3 | 人間の責任分担 | 0% / 5% / 50% / 100% | 5% |
  | 4 | 神の主管 | 常に直接 / 完成後のみ直接 / なし | 完成後のみ直接 |
  | 5 | 天使長の位置づけ | 人間より先・接触あり / 先・接触なし / 人間の後 / 創造しない | 先・接触あり |
  | 6 | 戒め | 与える / 与えない | 与える |
  | 7 | 堕落の可逆性 | 可逆 / 不可逆 | 可逆 |

- [ ] 組合せの総数は `3 × 2 × 4 × 3 × 4 × 2 × 2 = 1152` 通りである
- [ ] いずれかの値を変更すると、再読み込みなしに判定表示が更新される
- [ ] 既定値から変更したパラメータ行に変更マークが付き、
      「既定値から N 項目を変更中」と件数が表示される
- [ ] あるパラメータが他のパラメータによって**無効化**されたとき、
      その行がグレーになり、無効化の理由文がその行に表示される
- [ ] 無効化の理由文にも、根拠が原典由来か推論かの印が付く

### 判定の表示

- [ ] 「神が望んだもの」5 軸それぞれについて判定が表示される

  | # | 評価軸 | 内容 |
  |---|---|---|
  | 1 | 愛の対象の成立 | 授受作用が双方向に成立するか |
  | 2 | 神の子としての地位 | 自らの責任分担を果たした功として完成したか |
  | 3 | 三大祝福の成就 | 個性完成・家庭・被造世界の主管 |
  | 4 | 堕落の回避 | 堕落が起きずに済むか |
  | 5 | 神の喜び | 対象からの刺激としての喜びが成立するか |

- [ ] 判定は三値である。`○ 成立` / `✕ 構造的に不成立` / `△ 可能性はあるが保証されない`
- [ ] `✕` と `△` には、発火したルール**すべて**の理由文が表示される（1 本だけに省略しない）
- [ ] `✕` と `△` の各理由に、根拠となる原理の名前と出典の位置（書名・章節）が表示される
- [ ] `○` は「不成立とする根拠が無い」と表示される。`○` は出典を持たない

### 根拠の透明性

- [ ] 各根拠が「原典に明示的に書かれていること（明示）」なのか
      「原典の原則から推論で補ったもの（推論）」なのかが、区別して表示される
- [ ] **現在の判定に関わらず、全ルールを一覧する画面がある**
- [ ] その一覧で「推論」のルールだけに絞り込め、原典と突き合わせて検証できる
- [ ] 絞り込みの対象は、発火中のルールではなく全ルールである
- [ ] ローカルに原典資料が置かれている場合、出典位置に加えて引用本文が表示される
- [ ] 原典資料のファイルが存在しない場合も JavaScript の例外が発生せず、
      出典位置の表示だけで全機能が動作する
- [ ] 原典の引用本文はリポジトリに含まれない

### 中核の体験

- [ ] 1152 通りを総当たりして、`✕` を一つも含まない設定を抽出できる
- [ ] その設定群に**共通する値**が、実測の結果として一覧表示される
- [ ] `✕` の有無に影響しなかったパラメータが、実測の結果として区別表示される
- [ ] 抽出された設定群のすべてで「堕落の回避」がどの判定になるかが表示される
- [ ] 総当たりの結論がコードに埋め込まれておらず、
      ルールを 1 本変えると結論も変わる

> **注記（規範ではない）**
> 設計時点の想定では、`✕` ゼロの設定群は
> 「成長期間=あり / 責任分担=5% / 神の主管=完成後のみ直接 / 戒め=与える」を共通して持ち、
> そのすべてで「堕落の回避」が `△` になる。
> **これは期待であって受入条件ではない。** 実測がこれと食い違った場合、
> 直すのは実測結果ではなくルールの側か、この注記の側である。
> 結論をこの形にするためにルールを逆算してはならない。

### 創造の実行

- [ ] `✕` を含む設定で実行すると、選択画面に入らず、
      `✕` が立った軸それぞれについて「何が失われているか」が列挙される
- [ ] `△` を含む設定で実行すると、ユーザーがアダムの立場で選択する画面に入る
- [ ] 結果が乱数や自動判定で決まらない
- [ ] 選択画面の上部に、次の固定文が表示される

  > この設定では、結果は人間の選択によってのみ決まります。
  > 神の側に、この先の結果を決める手段はありません。

- [ ] 選択後の結果画面の末尾に、次の固定文が表示される

  > 神には、この結果を選ぶ手段がありませんでした。
  > あったのは、そうなることを望むことだけでした。

### 試行履歴

- [ ] 実行した試行が `localStorage` に保存され、**最新 20 件**まで保持される
- [ ] 画面に履歴の一覧があり、各行に「変更したパラメータの件数」「✕ の軸数」
      「選択の結果」が表示される
- [ ] 履歴の行を選ぶと、そのときのパラメータ設定が画面に読み込まれる
- [ ] 履歴を全件削除するボタンがある（個別削除は作らない）
- [ ] 保存領域が使えない環境（プライベートウィンドウ等）でも例外が発生せず、
      履歴以外の全機能が動作する

### 表示品質

- [ ] 幅 360px で横スクロールが発生せず操作できる
- [ ] ライトモードとダークモードの両方で全テキストが判読できる

## 非目標

**このタスクではやらないこと。**

### 内容面

- **教義の正しさを主張すること。** これは考察を支援する思考実験装置であり、
  布教や護教のための道具ではない
- **家庭連合以外の神学との比較。** キリスト教主流派の神義論、自由意志弁護論、
  イスラム、仏教などとの対照機能は作らない。将来拡張
- **原典テキストそのものをリポジトリに含めること。** 著作権があるため、
  ローカル限定・`.gitignore` 対象とする
- **神の心情を断定的に代弁すること。** 神の一人称で語る文章を書かない。
  記述は「原理から導かれる範囲」に留める

### 分量の上限（ここを決めないと実装が終わらない）

- **初版のルールは 24 本を上限とする。** 全パラメータ組合せを網羅しない。
  軸ごとに、判定を変える最小限のルールだけを書く
- **`narratives` の各文は 400 字程度を上限とする。**
  設定ごとの個別文言を作らない。共通の文 + 機械的な列挙で構成する
- **ルールの理由文は 1 本あたり 150 字程度を上限とする**

### 機能面

- **判定結果と考察の蓄積層（心情マップ）。** 将来拡張。
  今回は試行履歴の保存までとする
- **多視点対話盤。** 神／アダム／天使長／批判的視点の切り替えは作らない。
  「アダムの立場での選択」だけを中核の体験として今回に含める
- **LLM を呼ぶ動的な対話。** Claude API などは使わない。API キーも使わない
- **乱数による堕落シミュレーション。** 意図的に採らない。
  結果を確率で回すと「神には結果が分からなかった」という構造が壊れる
- **ルールやパラメータを画面から編集する機能。** データファイルを直接編集して行う
- **履歴の個別削除。** 全件削除のみ
- **判定結果の共有・エクスポート・公開ホスティング**
- **ログイン、サーバー、データベース**

## 制約

親の `~/projects/.claude/CLAUDE.md` および `static-zero` テンプレに従う。

- **npm 依存ゼロ。** ビルド工程を持たない（`build.mjs` も `package.json` も置かない）
- **オフライン完結。** CDN のスクリプト・フォント・画像を読まない
- **`file://` で開いて動く。** これが最優先の制約であり、次の 2 つを禁止する
  - `fetch()` — CORS で失敗する。データは `window.X = ...` 形式の `.js` として読む
  - `<script type="module">` — `file://` で動かない。IIFE + グローバルで書く
- **素の CSS。** プリプロセッサを使わない
- **DOM は `document.createElement` で組む。** `innerHTML` に外部由来の文字列を渡さない
- **公開対象は許可リスト方式。** 原典由来のファイルが誤って公開対象に入らないようにする

### 許容する例外

`data/sources.local.js` が未配置のとき、ブラウザのコンソールに
`net::ERR_FILE_NOT_FOUND` が出力される。これは `<script src>` の仕様上避けられない。
**JavaScript の例外が発生せず画面が正常動作すること**を条件とし、
このネットワークエラー表示は許容する。
