# 反証条件・開かれた問いへの仮説回答 / ダークモード既定化

規模: **M**（frontmatter に新しいキー = 新データ構造。記事 33 本 + 検証 + ビルド + 画面 3 枚）。

## 背景

ユーザーの依頼は二つ。

1. 反証条件に対する仮説回答と、開かれた問いに対する仮説回答を加える
2. ダークモードにする

調査で分かったこと。

- 反証条件は `falsifiers`（計 104 件）、開かれた問いは `questions`（計 132 件）。どちらも `list[str]`
- 本文の `## 反証条件` `## 開かれた問い` 節は散文で、配列と 1 対 1 ではない。回答を本文に足すと
  本文の上限 8000 字に当たる記事が出る。**本文には足さず、frontmatter に並行配列で持たせる**
- frontmatter は検査 C25 で未知キーを弾く。キーを足すには `REQUIRED_KEYS` と `EXPECTED_TYPES` を改める
- 生成物は `pick_article` の許可リスト方式。新キーもここで明示的に出す
- 問いは `data/questions.js` に横断集計され、`#/questions` に並ぶ
- ダーク配色のトークンは `tokens.css` に既にある。現状は OS 設定に従うだけで、
  `data-theme` を切り替える手段が無い
- `sw.js` の版は app shell のハッシュから自動で決まる。手で上げる必要はない

## 仮説回答の立て方

**回答は仮説であって、判定ではない。** この工房は真偽を判定しない。回答もその線を越えない。

- **反証条件への回答**: その条件が原典の読みで「現に満たされているか」を、本稿の暫定の読みとして答える。
  満たされていないと読む根拠、残る弱点（どこを突かれたら崩れるか）まで書く。
  「反証された／されていない」と断定しない。「〜と読む」「現時点では〜」の形にする
- **開かれた問いへの回答**: 一つの仮の答えを置き、それが何を新たに問わせるかで終える。
  **問いを閉じない。** 答えを置いても問いは一覧に残る
- 1 件 60〜250 字。原典の逐語引用は入れない（引用は `:::quote` 経由だけ。逐語検査を通らないため）
- 既存記事への言及は記事名で書く（`[[slug]]` 記法は frontmatter では展開されない）
- 文体は本文に揃える。短く言い切る

例（`adjunction` 反証条件 1）:

> 原典は主体と対象を、似ていることを資格とする特定の対として扱い、誰と誰でもよいとは書いていない。
> 現時点ではこの条件は満たされていない、と読む。ただし「似ている」の基準が緩ければ候補は増え、
> 一意性は「本質的に一つ」から「条件を満たす一群」へ弱まる。そこが最も突かれやすい。

## 受入条件

- [ ] 全 33 記事の frontmatter に `falsifier_answers` と `question_answers` を足す（どちらも `list[str]`）
- [ ] 長さはそれぞれ `falsifiers` / `questions` と一致し、i 番目が i 番目への回答になる
- [ ] 236 件すべてが上の「立て方」に従う。空文字を置かない

### 検証（`scripts/validate.py`）

- [ ] `REQUIRED_KEYS` と `EXPECTED_TYPES` に 2 キーを足す
- [ ] 検査 C28: 長さの一致・空でないこと・1 件 250 字以内（空白除去後）を検査する。違反は失敗

- [ ] `pick_article` が `falsifierAnswers` `questionAnswers` を出力する

- [ ] 回答は本文・問いと視覚的に区別する（左罫線＋ラベル）。`innerHTML` を使わない

### ダークモード

- [ ] 既定をダークにする（`<html data-theme="dark">`）

- [ ] `file://` でダブルクリックして開き、ダークで表示され、切替が効くこと

## 非目標

- 本文の `## 反証条件` `## 開かれた問い` 節は書き換えない
- 回答で反証条件・問いそのものを書き換えない・減らさない
- 回答に `:::quote` や原典の逐語を入れない。anchor も足さない
- 回答を検索対象に加えない
- 回答の真偽・妥当性を機械的に判定しない（検査は形式だけ）
- 配色トークンの値は変えない。ダーク配色の新規デザインはしない
- OS 設定に追従する第 3 の状態（自動）は作らない。ダーク／ライトの 2 択
- 仕様 `hypothesis-studio/` の design は改めない（検査表への C28 追記のみ）

## 検証方法

1. `python scripts/build.py` が検証を全件通り、`data/*.js` を更新する
2. 長さ不一致の記事を一時的に作り、C28 で失敗することを確かめて戻す
3. `index.html` を `file://` で開き、記事 2 本・`#/questions` で回答が出ること、ダーク表示・切替・再読み込み後の保持を確かめる
