# 仮説工房 — 設計

## 全体像

```
docs/                     原典（読み取り専用・非公開・.gitignore）
config/studio.json        論点・観点・地雷・既出対応づけの定義
hypotheses/<slug>.md      仮説記事（JSON frontmatter + 本文）
        │
        ▼
scripts/build.py          ① 検証 → ② Markdown変換 → ③ 集計 → ④ data/*.js 生成
        │
        ▼
data/*.js                 window.X = ... 形式（生成物・コミットする）
index.html + assets/      ビューア（file:// で動く）
```

**ビルドが通らなければ記事は公開されない。** 検証はビルドの一部であり、
後から走らせる別工程ではない。

---

## 記事の形式

### frontmatter は JSON

YAML パーサを標準ライブラリで持てないため **JSON** にする。
`json.loads` で読めるので、自前パーサのバグが入り込む余地が無い。

```
---
{
  "title": "神は創造を「試す」ことができたのか",
  "claim": "自由意志を含む系の帰結を知る近道は存在せず、試行は原理的に現実と同一になる。",
  "lens": ["計算論"],
  "topics": ["自由意志と責任分担", "成長期間と間接主管"],
  "mode": "構造的対応",
  "terrain": "空白地",
  "sources": [
    {
      "file": "原理講論/前編/02_創造原理.md",
      "anchor": "第五節 被造世界の創造過程とその成長期間",
      "label": "創造原理 第五節（二）被造物の成長期間"
    },
    {
      "file": "原理講論/前編/07_予定論.md",
      "anchor": "第二節 み旨成就に対する予定",
      "label": "予定論 第二節 み旨成就に対する予定"
    }
  ],
  "science": ["計算論的既約性 (Wolfram)", "停止性問題 (Turing)"],
  "mines": [
    { "id": "M-01", "touches": false, "reason": "偶然ではなく決定不能性に依拠する" },
    { "id": "M-06", "touches": false, "reason": "多宇宙を仮定せず、単一の系の既約性のみを扱う" }
  ],
  "known": [],
  "falsifiers": ["人間の意思決定が有限状態機械に還元できる場合、この仮説は成立しない。"],
  "questions": ["神が結果を知り得ないことは、全知の否定ではなく全知の内容の再定義か。"],
  "related": ["control-autonomy"]
}
---
```

`mines` は **全 7 件を必ず列挙する。** 空配列は禁止。
触れないなら `touches: false` と、なぜ触れないかを書く。
**「触れていないことを確認した」という事実を記事に残すのが目的**であり、
書き忘れと「検討していない」を区別するため。

### 本文の必須節

次の 8 つの `##` 見出しを、この順で持つ。各節の本文は 200 字以上。

```
## 問い
## 主張
## 前提
## 導出
## 原典との突き合わせ
## この仮説が言っていないこと
## 反証条件
## 開かれた問い
```

### 原典引用の専用記法

```
:::quote 0
（原典からの引用本文）
:::
```

数字は `sources` 配列の添字。**引用本文は原典の逐語でなければならない。**
ビルドが `sources[n].file` の中に、正規化後の完全一致で存在するかを検査する。

**ブロック引用（`>`）は著者自身の強調であり、引用の字数には数えない。**

### 照合の正規化規則

`anchor` と `:::quote` の本文は、照合の前に次を行う。

1. 半角空白・全角空白・タブ・改行をすべて除去する
2. 除去後の文字列で `in` 判定する

原理講論は 1 節が 1 行（10 万バイト級）、統一思想は OCR で空白が乱れているため、
空白を無視しないと照合が成立しない。

### 記事間の相互参照

`[[slug]]` で他の記事にリンクする。ビルドが参照先の実在を検査し、
**被リンク（backlinks）を逆算して各記事に持たせる。**

## `config/studio.json`

```json
{
  "topics": [
    "創造の動機", "自由意志と責任分担", "成長期間と間接主管", "堕落の機構",
    "神の悲しみ", "復帰と蕩減", "愛と授受作用の構造", "宇宙の自律的発展の機構"
  ],
  "lenses": ["計算論", "熱力学", "情報理論", "数学", "化学", "制御論", "物理", "複雑系"],
  "modes": ["比喩", "構造的対応", "経験的主張"],
  "terrains": ["空白地", "拡張", "留保地", "係争地"],
  "mines": [
    {
      "id": "M-01",
      "position": "偶然による発展",
      "note": "宇宙の発展が偶然的にこうなったとする見解を棄却している",
      "source": { "file": "統一思想/01_第一章 原相論.md", "anchor": "（実在する文字列を入れる）" }
    }
  ],
  "known": [
    {
      "id": "K-01",
      "pairing": "内的自同的授受作用 ＝ 強い力",
      "source": { "file": "宇宙論と統一思想/13_宇宙の発展してきた歴史.md", "anchor": "（実在する文字列を入れる）" }
    }
  ]
}
```

### 論点 8 件

「**宇宙の自律的発展の機構**」を含めるのが要点である。
原典は偶然による発展も純粋な法則的必然論も棄却したうえで、第三の道を
「自律的」とだけ呼び、**その機構を記述していない**。背景で「最大の入り口」と
呼んだのはここであり、論点語彙に無ければマトリクスにも現れない。

### 観点 8 件

「**複雑系**」を含める。初版 6 本では 1 本も割り当たらず、列が丸ごと空になる。
**それでよい。** 空白が見えることがマトリクスの目的であり、
調査で判明した最大の空白領域が画面に出ないほうが問題である。

### 地雷 7 件（原典が明示的に否定している立場）

| id | 否定されている立場 |
|---|---|
| M-01 | 偶然による発展 |
| M-02 | 純粋な法則的必然論 |
| M-03 | 一元論的唯物論／一元論的唯心論 |
| M-04 | 対立物の闘争による発展 |
| M-05 | 人間原理を物理法則と見なすこと |
| M-06 | マルチバースによる微調整の説明 |
| M-07 | DNA の合成＝生命の創造という主張 |

### 既出の対応づけ 7 件（新説として出してはいけないもの）

| id | 原典が既に持っている対応づけ |
|---|---|
| K-01 | 内的自同的授受作用 ＝ 強い力 |
| K-02 | 内的発展的授受作用 ＝ 弱い力 |
| K-03 | 外的自同的授受作用 ＝ 重力 |
| K-04 | 外的発展的授受作用 ＝ 電磁気力 |
| K-05 | 本性相・本形状 ＝ 陽子と中性子 |
| K-06 | 前エネルギー ＝ 真空のエネルギー |
| K-07 | 内的／外的授受作用 ＝ 自転／公転 |

記事が `known` に id を挙げた場合、その記事の `terrain` は `拡張` でなければ
ビルドが失敗する。**既出を空白地の新説として出すことを機械的に防ぐ。**

## ビルドの処理順

### 1. コーパスの読み込みと健全性の警告

`docs/` 配下の `.md` を読む。既知の欠損を**警告として**表示する
（ビルドは失敗させない）。

- `原理講論/前編/03_堕落論.md` に後編の緒論が混入している
- `原理講論/前編/07_予定論.md` の第一節が欠落している
- `原理講論/後編/04_…` の H1 と本文の章題が不一致
- `原理講論/前編/01_総序.md` に空の `## 後編` が残っている

**原典は絶対に書き換えない。** ビルドは docs を読むだけ。
欠損の修正・整形はしない（非目標）。

### 2. 検証

失敗は**全件集めてから**まとめて報告する。1 件目で止めない。

| # | 検査 | 失敗時 |
|---|---|---|
| 1 | frontmatter が JSON として読めるか | 失敗 |
| 2 | 必須キーが揃っているか（`topics` を含む） | 失敗 |
| 3 | `mode` が `経験的主張` でないか | 失敗 |
| 4 | `lens` / `topics` / `terrain` / `mode` が `studio.json` の語彙内か | 失敗 |
| 5 | 必須の 8 節が、この順で揃っているか | 失敗 |
| 6 | 各節の本文が 200 字以上か | 失敗 |
| 7 | 本文の総字数が 3000 字以上 8000 字以下か | 失敗 |
| 8 | `sources` が 2 件以上あるか | 失敗 |
| 9 | `sources[].file` が docs 配下に実在するか | 失敗 |
| 10 | `anchor` が 10 字以上 40 字以下か | 失敗 |
| 11 | **`anchor` が正規化後に当該ファイル内に実在するか** | 失敗。出現回数を表示 |
| 12 | `:::quote` が 1 箇所以上あるか | 失敗 |
| 13 | `:::quote n` の `n` が `sources` の範囲内か | 失敗 |
| 14 | **`:::quote` 本文が正規化後に `sources[n].file` に実在するか** | 失敗 |
| 15 | 引用 1 箇所が 200 字以内か | 失敗 |
| 16 | 引用合計が 600 字以内か | 失敗 |
| 17 | 同一 `sources[n]` からの引用が 1 記事 1 箇所までか | 失敗 |
| 18 | `falsifiers` が 1 件以上あるか | 失敗 |
| 19 | `questions` が 1 件以上あるか | 失敗 |
| 20 | `related` と `[[slug]]` の参照先が実在するか | 失敗 |
| 21 | `mines` に全 7 件の id が列挙され、各件が `touches` と `reason` を持つか | 失敗 |
| 22 | `touches: true` の件の `reason` が空でないか | 失敗 |
| 23 | `known` に id を挙げた記事の `terrain` が `拡張` か | 失敗 |
| 24 | `studio.json` の `mines[].source` と `known[].source` が実在するか | 失敗 |
| 26 | 記事の無いマスすべてが `cells` に `status` と `note` を持つか | 失敗 |
| 27 | `cells` の `status` が `planned` / `na` のいずれかか | 失敗 |
| 25 | 出力フィールドが許可リスト内に収まっているか | 失敗 |

成功時も「検査した項目と件数」を出す。
**何も検査せずに通ったのか、検査して通ったのかが区別できなければ意味がない。**

### 3. Markdown 変換

`四柱推命鑑定/scripts/markdown.py` を流用し、次の 2 つを足す。

- `:::quote n` ブロック → 引用 + 出典ラベル
- `[[slug]]` → 記事へのリンク

見出し id の採番と `strip_tags()` はそのまま使う。
**frontmatter 由来の文字列と引用本文は、埋め込む前に HTML エスケープする。**

### 4. 集計

- **backlinks**: `[[slug]]` と `related` から逆リンクを作る
- **questions**: 全記事の `questions` を、出典記事つきで 1 本の配列にまとめる
- **matrix**: `topics × lenses` = **8 × 8 = 64 マス**。各マスに `status` を付ける
  （`filled` / `planned` / `na`）。記事の有無が `cells` の指定より優先する
- **mines**: 各地雷に、`touches: true` の記事と理由を紐づける

### 5. 出力（許可リスト）

**`data/*.js` に出すフィールドはここに挙げたものだけ。** 列挙外のキーは出力しない。

`data/hypotheses.js` の 1 件:

| フィールド | 備考 |
|---|---|
| `slug` / `title` / `claim` | |
| `lens` / `topics` / `mode` / `terrain` | |
| `science` / `falsifiers` / `questions` / `related` / `backlinks` | |
| `sources[].label` / `sources[].file` | **`anchor` は出力しない** |
| `mines[].id` / `touches` / `reason` | |
| `known` | id のみ |
| `bodyHtml` | エスケープ済み |
| `plain` | 検索用の素文 |
| `chars` | 本文字数 |

**`anchor` を出力しない理由:** `anchor` は原典の逐語である。
検証のために必要なだけで、公開物に載せる必要がない。
出力しなければ、生成物に混入する原典の逐語は `:::quote` の引用だけに限定され、
字数制限が実際に効く。

他の出力: `data/studio.js`（`anchor` を除いた語彙定義）/ `data/matrix.js` /
`data/questions.js`。

1 行目に `/* AUTO-GENERATED by scripts/build.py — DO NOT EDIT */` を入れ、
**生成物もコミットする**（`file://` で開くため）。

検証が失敗したときは `data/*.js` を書き換えない。

## ビューア

### 画面とルート（6 つ。増やさない）

| ルート | 画面 |
|---|---|
| `#/` | 仮説の一覧。`lens` / `mode` / `terrain` で絞り込み |
| `#/h/<slug>` | 記事本文。目次・出典・被リンク |
| `#/questions` | **問い一覧**。全記事の問いを横断 |
| `#/matrix` | **観点マトリクス**。64 マス。空白が見える |
| `#/mines` | 地雷一覧と、触れている記事 |
| `#/search?q=` | 全文検索 |

### 描画の方針（`innerHTML` の扱い）

流用元の `router.js` は `viewRoot.innerHTML = view.html` で描画し、
`dom.js` はテンプレートリテラル前提で書かれている。**そのままでは使えない。**

決めごと:

- **`innerHTML` を使うのは `views/article.js` の本文挿入 1 箇所だけ。**
  ここに入るのは自分のビルドが自分の `hypotheses/*.md` から生成した HTML であり、
  外部由来ではない。エスケープはビルド側で済ませてある
- **`router.js` は改修する。** view 関数が HTML 文字列ではなく **DOM ノードを返す**形にし、
  `viewRoot.replaceChildren(node)` で差し替える
- **`dom.js` / `partials.js` は `createElement` ベースに書き直す。** 流用ではなく参考扱い
- それ以外の全 UI は `createElement`

### 流用するもの（改修の有無を明記）

| 流用元 | 改修 | 内容 |
|---|---|---|
| `四柱推命鑑定/scripts/markdown.py` | **あり** | `:::quote` と `[[slug]]` を追加 |
| `四柱推命鑑定/assets/js/search.js` | **あり** | `Store.readings` / `Store.typeEn(r.type)` / `r.typeLabel` という占い固有のフィールド名がインデックス構築に埋まっている。`hypotheses` 用に差し替える |
| `四柱推命鑑定/assets/js/router.js` | **あり** | `innerHTML` をやめ、DOM ノードを返す形にする。ルート定義も差し替え |
| `四柱推命鑑定/assets/js/toc.js` | なし | 目次の自動追従と読了進捗 |
| `四柱推命鑑定/assets/js/dom.js` | **書き直し** | テンプレートリテラル前提。`createElement` 版を新規に書く |
| `四柱推命鑑定/assets/js/views/partials.js` | **書き直し** | 同上。カード・チップの構造だけ参考にする |
| `四柱推命鑑定/scripts/build.py` | **あり** | 骨組みのみ。占い固有のフィールドは外す |

### `store.js` が公開するキー

```js
window.Store = {
  hypotheses,        // 配列
  bySlug,            // slug → 記事
  studio,            // 語彙定義
  matrix,            // 64 マス
  questions          // 問い一覧
}
```

`search.js` はこの名前に合わせて改修する。**`readings` という名前を残さない。**

### 記事冒頭の常時表示

```
[構造的対応]  [空白地]   観点: 計算論
```

`比喩` と `構造的対応` は色を変える。**読者が最初に見るべきなのは、この仮説が
何を主張していて何を主張していないかである。**

| `transition-state` | 成長期間中の人間は準安定状態。堕落は自発的、復帰は非自発的で外部からのエネルギー注入を要する。蕩減＝活性化エネルギー |
| `irreversibility` | 可逆な出来事に悲しみは生じない。神の悲しみの強度を時間の非対称性の側から捉える |
| `control-autonomy` | 完全に制御された系は自律性を持たない。愛の対象の要件と制御可能性はトレードオフである。原典が記述しない「自律的発展の機構」の候補を置く |
| `symmetry-breaking` | 創造を対称性の自発的破れとして読む。二性性相との接続を試みるが、比喩に留める |
| `mutual-information` | 授受作用の強度を相互情報量として定式化する。K-01〜K-04 の延長に置き、新説として出さない |

## 検討した代替案

| 案 | 採らなかった理由 |
|---|---|
| 見出しをアンカーに使う | 原理講論は Markdown 見出しをほぼ持たず、統一思想の見出しは OCR で採番が壊れている。成立しない |
| `anchor` を生成物に出力する | `anchor` は原典の逐語。出力しなければ、生成物に載る逐語は `:::quote` だけになり字数制限が実際に効く |
| YAML frontmatter | 標準ライブラリに YAML パーサが無い。自前実装はバグの温床 |
| 引用をブロック引用で書く | 著者自身の強調と区別できず、字数制限を機械的にかけられない |
| `innerHTML` を全面禁止する | 本文 HTML の描画手段が無くなる。1 箇所に限定し、経路を明示するほうが守れる |
| `innerHTML` を自由に使う | 流用元がそうだが、外部由来文字列との境界が曖昧になる。1 箇所に閉じる |
| `mines` を空配列で許す | 書き忘れと「検討して触れないと判断した」が区別できない。全 7 件の列挙を強制する |
| ビルドを Node の `build.mjs` にする | 流用したい `markdown.py` が Python 製。Python 3.11 が環境にあり標準ライブラリだけで動く |
| 検証を別コマンドに分ける | 分けると走らせ忘れる。ビルドの一部にする |
| 検証の失敗を 1 件目で止める | 直しては走らせ直す往復が増える。全件まとめて報告する |
| 観点に `複雑系` を入れない | 調査で判明した最大の空白が画面に出ない。1 本も割り当たらなくても列として置く |
| 論点に「自律的発展の機構」を入れない | 背景で「最大の入り口」と呼んだ論点がマトリクスに現れなくなる |
| 原典の全文をビューアに載せる | 著作権。引用部分のみを扱う |
| 仮説の真偽を判定する機能を持つ | 判定できない。整合性・反証条件・出典実在の検査まで |
| LLM をランタイムで呼ぶ | オフライン制約に反する。仮説は Claude Code のセッション内で書く |
| マトリクスを埋まったマスだけ表示する | 空白が見えることがこの画面の目的 |
