# 仮説工房 — 要件

## 背景

家庭連合／統一思想の枠組みで「神の心情と人間創造」を考察したい。
求めているのはパラメータを回すシミュレータではなく、**仮説を作り、記事に仕上げ、
問いを立て、視点を切り開く**装置である。

加えて、物理学・数学・計算科学の観点を交えた理論的仮説を立てたい。

調査により、次のことが分かった。これが設計の前提になる。

### 原典は既に物理学へ深く踏み込んでいる

`docs/宇宙論と統一思想` と `docs/統一思想` には、既に具体的な対応づけがある。

| 原理概念 | 対応づけ済みの物理 |
|---|---|
| 内的自同的授受作用 | 強い力 |
| 内的発展的授受作用 | 弱い力 |
| 外的自同的授受作用 | 重力 |
| 外的発展的授受作用 | 電磁気力 |
| 本性相・本形状 | 陽子と中性子 |
| 前エネルギー | 真空のエネルギー |
| 内的／外的授受作用 | 自転／公転 |

**既に言われていることを新説として出してはいけない。**

### 原典が扱っていない領域が特定できた

全 21 ファイルで該当語が 0 件だった領域。

- 熱力学・エントロピー（**最大の空白**。宇宙の方向性を論じながら第二法則に触れていない）
- 対称性の自発的破れ（二性性相を扱い素粒子論を引くのに、この語だけ欠落）
- 情報理論（情報量・ビット・シャノンエントロピー）
- 計算量理論・アルゴリズム（「計算としての創造」という枠が未使用）
- カオス・複雑系・自己組織化・創発
- 非平衡熱力学・散逸構造

**そして原典は「宇宙は自律的・目的論的に発展する」と主張しながら、その機構を記述していない。**
偶然による発展も純粋な法則的必然論も明示的に棄却したうえで、第三の道を
「自律的」とだけ呼んでいる。ここが最も大きな入り口である。

### 踏んではいけない立場が特定できた

原典が明示的に否定している立場（`data/mines.js` としてデータ化する）。

- 偶然による発展
- 純粋な法則的必然論
- 一元論的唯物論／一元論的唯心論
- 対立物の闘争による発展（授受作用は調和的であり相衝的ではない）
- 人間原理を物理法則と見なすこと
- マルチバースによる微調整の説明（「逃避的」と明言）
- DNA を合成すれば生命を造ったことになるという主張

## このツールが主張しないこと

**画面に常時表示する固定文（文言を仕様で確定する）:**

> ここにあるのは仮説です。真理の主張ではありません。
> 各仮説には、それが原典の記述なのか、このツールの推論なのか、
> 科学の比喩にすぎないのかが明示されています。
> 反証条件のない仮説は、この工房には置かれません。

## 受入条件

### 動作の基本

- [ ] `index.html` をダブルクリックして開くと、ローカルサーバーなしで全機能が動作する
- [ ] ブラウザをオフラインにしても全機能が動作する
- [ ] 上記の固定文が画面の所定位置に常時表示されている
- [ ] `python scripts/build.py` の 1 コマンドでビルドが完了する
- [ ] ビルドは Python 標準ライブラリのみで動く（pip install を必要としない）

### 仮説記事の構造

- [ ] 仮説は `hypotheses/<slug>.md` に 1 本 1 ファイルで置く
- [ ] 各記事は frontmatter に次を持つ。**一つでも欠けるとビルドが失敗する**

  | 項目 | 内容 |
  |---|---|
  | `title` | 表題 |
  | `claim` | 主張を 1 文で |
  | `lens` | 観点。`studio.json` の語彙から選ぶ。1 件以上 |
  | `topics` | 論点。`studio.json` の語彙から選ぶ。1 件以上 |
  | `mode` | `比喩` / `構造的対応` / `経験的主張` |
  | `terrain` | `空白地` / `拡張` / `留保地` / `係争地` |
  | `sources` | 原典の出典。`file` / `anchor` / `label` の組。1 件以上 |
  | `science` | 科学側の典拠 |
  | `mines` | **全 7 件の地雷 id を必ず列挙**し、各件に `touches`（真偽）と `reason` を書く。空配列は禁止 |
  | `falsifiers` | 反証条件。**1 件以上必須** |
  | `questions` | 開かれた問い。**1 件以上必須** |
  | `related` | 関連する仮説の slug |

- [ ] 本文は次の節を持つ。**欠けるとビルドが失敗する**

  1. 問い
  2. 主張
  3. 前提（原典から / 科学から）
  4. 導出
  5. 原典との突き合わせ（支持する箇所 / 緊張する箇所）
  6. **この仮説が言っていないこと**
  7. 反証条件
  8. 開かれた問い

### ビルド時の検証（ここが「検証」の実体）

- [ ] frontmatter の必須項目が欠けているとビルドが失敗し、ファイル名と欠落項目を表示する
- [ ] 本文の必須節が欠けているとビルドが失敗する
- [ ] `sources` が指す **docs 配下のファイルが実在するか**を検査する。存在しなければ失敗する
- [ ] `sources` の `anchor`（原典に実在する文字列そのまま）を原典ファイル内で検索し、
      **1 回も見つからなければビルドが失敗する**。出現回数を表示する
- [ ] `anchor` は **10 字以上 40 字以下**。短すぎる照合と、長すぎる逐語複製の両方を防ぐ
- [ ] 照合の前に空白類（半角・全角・改行）を除去して比較する。OCR 由来の空白揺れで落ちない
- [ ] **`:::quote n` の引用本文も、同じ正規化で `sources[n].file` に実在するかを検査する。**
      一致しなければ失敗する（誤記・要約・捏造を検出する）
- [ ] 同一の `sources[n]` からの引用は、1 記事につき 1 箇所までとする
- [ ] 原典の見出し構造に依存しない。原理講論は Markdown 見出しをほぼ持たず、
      統一思想の見出しは OCR で壊れているため、見出しをアンカーに使わない
- [ ] `related` の参照先 slug が実在しなければ失敗する
- [ ] `mode` が `経験的主張` の記事はビルドを失敗させる（非目標）
- [ ] `falsifiers` または `questions` が空なら失敗する
- [ ] `sources` が 2 件未満なら失敗する
- [ ] `:::quote` が 1 箇所も無ければ失敗する
- [ ] 必須 8 節のいずれかの本文が **200 字未満**なら失敗する
- [ ] 本文の総字数が **3000 字未満または 8000 字超**なら失敗する
- [ ] `mines` に全 7 件の id が列挙されていなければ失敗する
- [ ] `config/studio.json` の `mines[].source` も、記事の `sources` と同じ実在検査に掛ける
- [ ] **原典が既に持っている対応づけ**（四つの力＝四種の授受作用 など 7 件）を
      `config/studio.json` に `known` として持ち、それを扱う記事の `terrain` が
      `拡張` でなければ失敗する。既出を新説として出すことを防ぐ
- [ ] 原典からの引用が **1 箇所あたり 200 字を超える**と失敗する（著作権）
- [ ] 1 記事あたりの引用の合計が **600 字を超える**と失敗する
- [ ] 検証の結果は、成功時も「検査した項目と件数」を表示する
- [ ] `data/*.js` に出力するフィールドは design に明示列挙されたものだけとする（許可リスト方式）。
      列挙外のキーが出力されていないことを検査する
- [ ] 既知のコーパス欠損（前編03への後編緒論の混入、前編07の第一節欠落、
      後編04のH1と章題の不一致）を、ビルド時に警告として表示する。
      警告はビルドを失敗させない

### ビューア — 読む

- [ ] 仮説の一覧が表示され、`lens` / `mode` / `terrain` で絞り込める
- [ ] 記事本文が読め、見出しから目次が自動生成される
- [ ] 本文中の原典引用に、出典（`label`）が併記され、どのファイルのどの箇所かが分かる

- [ ] `[[slug]]` 記法で記事間を相互参照でき、リンクとして機能する
- [ ] 各記事の末尾に、その記事を参照している他の記事（被リンク）が表示される
- [ ] 全文検索ができる
- [ ] `docs/` の原典本文そのものはビューアに含まれない（引用部分のみ）

### ビューア — 視点を開く

- [ ] **問い一覧**: 全記事の `questions` を横断で集めた画面がある
- [ ] 問いから、それを出した記事へ移動できる

      `status`（`planned` / `na`）と `note`（理由）を持つ。**持たないマスがあるとビルドが失敗する**
- [ ] 空白が「手つかず」ではなく「判断の結果」として読める
- [ ] **地雷一覧**: 原典が否定している立場の一覧と、それに触れている記事が表示される

## 非目標

### 内容面

- **仮説の真偽を判定すること。** このツールは真偽を決めない。
  できるのは整合性の検査・反証条件の明示・出典の実在確認までである
- **教義の正しさを主張すること**
- **神の一人称で語る創作的な心情描写**
- **`経験的主張` モードの仮説を書くこと。** 現実世界についての検証不能な主張は置かない。
  ビルドで弾く
- **原典が否定する立場を、否定と知らずに踏むこと。** 踏むなら `係争地` として
  理由を明記する
- **家庭連合以外の神学との比較**（将来拡張）
- **原典テキストをリポジトリに含めること。** `docs/` は `.gitignore` 対象

### 機能面

- **ブラウザ上で記事を編集する機能。** 記事は `.md` を直接書き、ビルドで反映する
- **LLM をランタイムで呼ぶこと。** API キーを使わない。
  仮説を書くのは Claude Code のセッション内であって、公開されたページではない
- **コメント・共有・公開ホスティング・ログイン・サーバー・DB**
- **画面を増やすこと。** design の 6 ルートのみ。実装中に追加しない
- **検査項目を増やすこと。** design の検査表にあるものだけ。実装中に増やさない
- **関係グラフ・ネットワーク図。** `[[slug]]` と backlinks があると作りたくなるが、作らない
- **原典の誤りの修正・整形。** OCR 崩れや混入は**警告表示までで、直さない**
- **タグ・お気に入り・読了管理**
- **原典の全文ビューア。** 引用部分のみを扱う
- **自動的な仮説生成。** 仮説は人と Claude が書く。ツールが量産しない

### 分量の上限

- **全 64 マスを埋めることはしない。** 空白が見えることがマトリクスの目的であり、
  埋め尽くすと情報量がゼロになる。無理に立てた仮説は、反証条件も出典も
  「検証を通すため」に用意されることになり、基準そのものを腐らせる
- **仮説は 16 本まで。** 初版 6 本 + 分類後に選んだ 10 本
- **1 記事は 3000 字以上 8000 字以下。** 範囲外はビルドが失敗する（警告ではない）
  （当初 1200〜4000 字としていたが、浅い記事を通さないため実装中に引き上げた）
- **引用は 1 箇所 200 字 / 1 記事合計 600 字まで**（ビルドで強制）

## 制約

- **npm 依存ゼロ。** ビルドは Python 3.11 標準ライブラリのみ
- **オフライン完結。** CDN を読まない
- **`file://` で開いて動く。** `fetch()` と `<script type="module">` を使わない。
  データは `window.X = ...` 形式の `.js` としてビルドで生成する
- **素の CSS。** プリプロセッサを使わない
- **DOM は原則 `document.createElement`。** ただし記事本文の HTML は、
  自分のビルドが自分の `hypotheses/*.md` から生成したものであり、外部由来ではない。
  **`innerHTML` の使用は `assets/js/views/article.js` の本文挿入 1 箇所に限る。**
  そこ以外で `innerHTML` を使わない。ビルド側は、frontmatter 由来の文字列と
  原典引用を HTML エスケープしてから埋め込む
- **公開対象は許可リスト方式**
- **`docs/` の原典は読み取り専用。** ビルドは docs を書き換えない

## 検証方法

### 静的に確かめるもの（grep で件数を数える）

| 確かめること | 方法 | 期待 |
|---|---|---|
| `fetch` を使っていない | `index.html` と `assets/` を `fetch(` で grep | 0 件 |
| ES modules を使っていない | 同上を `type="module"` で grep | 0 件 |
| 外部リソースを読んでいない | 同上を `cdn` と `https://` で grep | 0 件 |
| `innerHTML` が 1 箇所に限られている | `assets/js/` を `innerHTML` で grep | 1 件（`views/article.js` のみ） |
| 原典本文が生成物に流出していない | `data/*.js` を原典の長い一節で grep | 0 件 |
| 原典を書き換えていない | ビルド前後で `docs/` の更新日時を比較 | 変化なし |

### ビルドで確かめるもの

`python scripts/build.py` を実行する。検証 16 項目の結果が件数つきで表示される。
**わざと壊した記事を用意して、失敗が全件まとめて報告されることを確かめる。**

### ブラウザで確かめるもの

**`file://` で直接開いて確かめる。** Playwright は `file://` を開けないため使わない。
**claude-in-chrome** で `file://` の絶対パスを開く。

| 確かめること | 方法 |
|---|---|
| ローカルサーバーなしで動く | `file://` で開き、全 6 ルートを遷移する |
| JavaScript の例外が出ない | コンソールを読む（`net::ERR_FILE_NOT_FOUND` は対象外） |
| オフラインで動く | DevTools を Offline にして全機能を通す |
| 幅 360px で崩れない | ウィンドウ幅を 360px にして横スクロールの有無を見る |
| 明暗どちらでも読める | 本文と背景のコントラスト比が両モードで 4.5:1 以上 |
| 行長が適切 | 記事本文の `max-width` が 40em 以下 |
